## What it does

Miku Figures is a searchable, filterable archive of the Hatsune Miku figures listed by three retailers (see [Vendors](#vendors)). Standard-library Python scrapers run daily via GitHub Actions at 3 AM SGT, enriching each figure with detail-page data and writing the results to `public/figures.json`. The React + Vite frontend reads that static JSON and lets collectors browse, filter, and sort the full catalogue without a backend server.

## Features

- Figure catalogue scraped from HLJ, Solaris Japan and Latendo, updated daily via GitHub Actions cron
- A *Vendors checked* panel showing each retailer, how many figures it contributes and its price currency
- Incremental scraping mode — only fetches figures not already in the dataset, keeping runs fast
- Filter by figure type, series/event, illustrator, manufacturer, year range, and max price (SGD); series and illustrator chips are built from the data
- Dark and light themes (Julian Unified UI), following the OS setting until you pick one
- Sort by newest, oldest, name, manufacturer, or price
- Grid and list view modes
- Rich data schema per figure: scale, price, JPY and SGD price, JAN barcode, illustrator (when the name credits one), tags, and more
- Deployed as a static site (Vite build served via Nginx in Docker)

## Quick Start

### Run the scraper

```bash
cd scraper
pip install -r requirements.txt

# Full scrape — all figures (~30–60 min, polite rate limiting)
python hlj_scraper.py

# Incremental — only new figures since last run
python hlj_scraper.py --incremental

# Test run — 3 pages only
python hlj_scraper.py --limit 3
```

This writes `public/figures.json` and `public/meta.json`.

### Run the frontend

```bash
npm install
npm run dev
```

## Data Schema

Each figure in `figures.json`:

```json
{
  "id":              "12345",
  "name":            "Hatsune Miku: Symphony 2022 Ver.",
  "manufacturer":    "Good Smile Company",
  "release_date":    "2023-03",
  "year":            2023,
  "type":            "Scale",
  "scale":           "1/7",
  "price_jpy":       19800,
  "image_url":       "https://www.hlj.com/productimages/gsc/gsc59431_0.jpg",
  "price_sgd":       245.02,
  "detail_url":      "https://www.hlj.com/...",
  "illustrator":     "Rella",
  "tags":            ["Scale", "Symphony", "Rella", "Good Smile Company"],
  "dimensions":      "230mm",
  "material":        "PVC/ABS",
  "source":          "hlj"
}
```

> **Second source:** `scraper/solaris_scraper.py` adds figures HLJ does not carry from Solaris Japan (a Shopify store; its `agents.md` allows read-only browsing). It is slow on purpose (3.5 s between requests, honours 429 `Retry-After`) and fetches at most 300 new products per run, so the backlog fills over a few daily runs. Rows carry `source` (`hlj` / `solaris`); a Solaris item whose JAN barcode HLJ already has is skipped. Solaris prices are USD (`price_usd`) and have no release date.

> **Third source:** `scraper/latendo_scraper.py` adds figures from Latendo (Singapore, an Odoo store, prices in SGD). Latendo's robots.txt disallows shop search, pagination and category filters, so the scraper reads the sitemap and fetches only product pages whose URL mentions Miku (3 s apart, at most 200 per run). Pre-orders are kept. Latendo shows no JAN barcode, so rows HLJ or Solaris already carry are matched by name: the titles must share at least 75% of their words, with years, variant letters, catalogue codes and series (Snow / Racing / ...) agreeing exactly, and the same scale and product line. Matches and goods go into `latendo_skip.json`. A Latendo row is dropped later if another source picks the figure up.

> **Why HLJ:** MyFigureCollection blocks automated clients (403 / security check, including headless browsers from GitHub runners), so it can't be scraped. HLJ serves plain HTML. Prices are stored as `price_jpy` and `price_sgd` (HLJ's SGD display price); the UI shows SGD. HLJ has no illustrator or owner counts, so those fields are mostly empty.

## Vendors

| Vendor | Site | Prices | How it is read |
|---|---|---|---|
| HobbyLink Japan | hlj.com | SGD (and JPY) | Search listings, then product pages |
| Solaris Japan | solarisjapan.com | USD | Shopify search + product JSON; JAN duplicates skipped |
| Latendo | latendo.com | SGD | Sitemap + product pages; name duplicates skipped |

To add a vendor: write `scraper/<vendor>_scraper.py` that reuses `hlj_scraper`'s `classify` and `write_outputs`, add a step to `.github/workflows/daily_scrape.yml`, and add an entry to `VENDORS` in `src/App.jsx`.

Series/event and illustrator tags come from `EVENT_KEYWORDS` and `ILLUSTRATORS` in `scraper/hlj_scraper.py`. Every scraper re-tags all rows when it writes, so a list change applies to the whole archive on the next run.

## Manual scrape

The **Start Scrape** button in the app header opens the *Daily Figure Scrape* workflow on GitHub; click **Run workflow** and choose `incremental` or `full`. (Triggering it straight from the browser would need a GitHub token in the page, so it is deliberately a link.)

## Deployment

Frontend is deployed to **Cloudflare Workers** at [miku-figures.thebooleanjulian.dev](https://miku-figures.thebooleanjulian.dev) (deploy with `wrangler deploy`; push-to-deploy is not yet configured, so a scrape commit does not redeploy automatically). Vercel is no longer used.

A **Dockerfile** is also provided for serving the Vite build via Nginx:

```bash
docker build -t miku-figures .
docker run -p 8080:80 miku-figures
```
